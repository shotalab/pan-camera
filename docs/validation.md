## 自動テストとビルド

```sh
uv run python -m unittest discover -s tests -v
pio run -d firmware/m5stack
```

テストには一時ファイル、モック、生成映像・音声を使い、実機のカメラ・マイク・サーボは使いません。FFmpeg・ffprobeがない環境では該当する結合テストをスキップします。テスト件数と成功・スキップ数は実行結果を正とします。

| テスト | 確認する不具合・境界 |
|---|---|
| `test_controller.py` | 中央停止帯、小さな補正、大きなずれ、校正範囲、対象消失 |
| `test_smooth_servo.py` | 加減速、目標を超えない移動、反転、保持、スレッド終了 |
| `test_actuator.py` | PWMの初期化・停止・範囲制限、排他、保持の引き継ぎ |
| `test_camera.py` | 初期化失敗・解像度不一致・切断、最新フレーム取得、元JPEGの保持 |
| `test_app_stop.py` | 起動失敗時にPWMを有効化しないこと、追尾停止・選択・カメラ切断時の状態遷移 |
| `test_protocol.py` | 映像パケットのヘッダーと分割・再構成 |
| `test_detection_config.py` | 検出対象のON/OFF・引数優先、不正設定、種別・IDの抽出 |
| `test_launcher.py` | 二重起動防止、終了要求、不正・古い要求の拒否、異常終了後の再起動 |
| `test_recording.py` | 開始失敗の巻き戻し、キュー容量、録画の無効化、保存・音声エラー時の終了、動画の形式と時刻 |
| `test_display.py` | 映像領域の保持、状態表示、実時間に合わせた4 FPS保存、AVIの読み出し |

## 性能計測

コップ検出・サーボ無効・録画なしで提供されたログです。

```sh
uv run python -m pan_camera --profile --fps 0 --frames 300
```

1280×720 MJPEG、YOLO入力320、CPU推論。約270フレームでCtrl+C終了しており、300フレーム完走の測定ではありません。初期化を除いた5秒窓の値を示します。

| 指標 | 実測範囲 |
|---|---|
| カメラ取得 | 16.5～16.7 FPS |
| ループ全体 | 12.5～12.9 FPS |
| YOLO＋ByteTrack | 70.0～72.5 ms／回 |
| 指令計算などの後処理 | 約0.1 ms／回 |
| プレビュー送信 | 4.2～4.4 FPS |
| プレビュー描画・送信 | 平均7.2～7.3 ms／ループ（送信しない回を含む） |
| 取得完了から指令計算完了まで | 99.6～103.6 ms |

FPSは足し合わせる値ではありません。この遅延には露光・カメラ内部の待ち時間、実際のサーボ移動、M5Stack表示の遅延を含みません。カメラが列挙する30 FPSは対応モードの値で、アプリの取得FPSの保証ではありません。

H.264録画と追尾を併用した別の提供ログでは約8.4～9.8 FPSでした。画面再現AVIの追加前の値で、3種類の録画を併用した最新構成の性能は未測定です。

## 録画と音声

| 確認方法 | 結果 |
|---|---|
| 生成JPEG＋生成音声 | copyモードでJPEGバイト列の一致、H.264モードでデコード、両モードで映像の投入間隔と保存時刻の一致を確認 |
| 0.8秒の起動遅延＋重い720p JPEG | 40フレームを欠落なく保存。既定のキューは60フレーム・32 MiB以内 |
| 生成映像＋実機マイク、約3秒 | MJPEG＋PCMのMKV、H.264＋AACのMP4を保存。音声は48 kHz・モノラル |
| 実録画の圧縮比較 | 24.637秒のMKV 102.36 MiB → MP4 6.26 MiB。オフライン変換に約5.03秒 |
| 画面再現の描画のみ | Piで100枚の平均が約1.00 ms／枚。JPEG復号・AVI保存・推論との競合を含まない |

圧縮比較はlibx264 ultrafast・CRF 26・2スレッド、AAC 96 kbpsで実施しました。現在の録画中圧縮は短いキーフレーム間隔と低遅延設定も加えており、同じ容量・速度になる保証はありません。

短い実機マイク確認では、音声開始が映像より約1.002秒遅れる例がありました。長時間の同期・音質は未検証です。認識枠付きAVIは固定FPSで、特に `--fps 0` では8 FPS保存のため、実時間と再生時間が一致しない場合があります。枠なし映像と画面再現AVIは別の時刻処理を使います。

画面再現AVIはPiの映像と状態による近似で、M5Stackの受信落ち、メニュー、一時通知は含みません。
